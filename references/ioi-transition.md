# 从 NOI 转 IOI：8 周补强计划

> 读这个文件当且仅当：用户已在中国体系里（省一以上、省队、NOI 奖牌），目标转向 IOI / USACO Platinum / APIO，或问"我 NOI 打得好，为什么 IOI 题不会做"。
> 这不是"再学几个算法"的问题。**IOI 与 NOI 的差异在赛制、题型和评分模型，不在难度。** 一个 NOI 银牌选手第一次打 IOI 赛制的题，最常见的死法是完全不会用子任务。

## 一、四个结构性差异（先认清，再训练）

| 维度 | NOI / 中国 OI | IOI |
| --- | --- | --- |
| 输入输出 | `freopen` 读文件，绝大多数题有 `.in/.out` | **没有 stdin/stdout**，只能经题目给的 grader 函数；读写文件判 Protocol Violation |
| 语言 | C++（STL 允许） | **只有 C++**（Java 2021 起取消） |
| 评分 | 按测试点给部分分，赛后统一评测 | 按 subtask 给分，**赛中实时可见**，且每个 subtask 取**历次提交的最大值** |
| 题型 | 传统 IO 题为主 | 传统题 + **交互题** + **提答题（OutputOnly）** + **通信题** |

后两条决定了策略：IOI 里"先交暴力"是纯赚，"一次写完再交"是纯亏。

## 二、8 周计划

前提：算法基础已具备（省队水平），这 8 周**不学新算法**，只改习惯与题型。

| 周 | 主题 | 具体动作 | 验收 |
| --- | --- | --- | --- |
| 1 | 规则与 grader | 读 IOI 竞赛规则与 CMS 文档；手写一个 grader 版的 A+B（`int solve(int a, int b)`）；跑通一次编译-提交循环 | 能在没有 `main` 的情况下写出可编译的 `solve` |
| 2 | 子任务拆解 | 取 3 道 IOI 真题，**只读题面与 subtask 表**，为每档写出"需要的复杂度 + 预计得分"，不写代码 | 3 道题的子任务规划与实际得分误差 ≤ 20% |
| 3 | 暴力工程 | 每题先写最裸暴力并提交，再逐档优化；练习"20 分钟内交出第一版" | 连续 5 题都在 30 分钟内拿到非零分 |
| 4 | 交互题 | 二分式交互（猜数类）、随机化交互；`flush` 与询问次数预算；本地写交互器自测 | 独立完成 3 道交互题，询问次数不超限 |
| 5 | 提答 / 输出型 | 构造 + 局部搜索 + 模拟退火；理解"分批提交、保留最优"的规则 | 提答题拿到满分的 70% 以上 |
| 6 | 通信题 | 信息编码、下界估算、消息长度预算；双进程本地模拟 | 能说清"为什么这个方案的消息数是最优量级" |
| 7 | 英文题面 | 每天精读 1 道长题面（IOI/CEOI/USACO Platinum），限时 20 分钟写出一句话题意 + 数据范围 + 子任务结构 | 20 分钟内读懂并复述 3 道陌生题 |
| 8 | 全真模拟 | 两天各 3 题 5 小时，中间隔一天；严格按 IOI 规则（不可访问网络、无 stdin/stdout） | 两天总分 ≥ 300/600，且每题都有分 |

## 三、中国选手最常踩的五个坑

1. **习惯性写 `freopen`**。IOI 环境里这直接 0 分（Protocol Violation）。第 1 周就要把手感改掉：所有练习都写成 `solve()` 形式。
2. **"一次写完再交"的心态**。NOI 赛制没有反馈，养成了"憋大招"；IOI 里每次提交都只赚不亏，先交暴力是标准动作。
3. **不看子任务表**。子任务结构就是出题人给你的得分路线图：先看每档的 n 范围，按"复杂度—分数"排序，而不是按题号顺序做。
4. **不会写交互题的本地测试**。交互题必须自己写一个交互器（或用人家的 grader 模板）在本地跑，否则永远在盲交。
5. **忽略提答题**。提答题不考算法考工程：构造 + 爬山 + 多组参数，能稳定拿 60–80 分，是拉开差距的地方。

## 四、哪些继续练，哪些降级

| 内容 | 处置 |
| --- | --- |
| DP 全套、图论、数据结构（线段树/树状数组/并查集/堆） | **继续练**，IOI 的核心 |
| 构造、贪心证明、复杂度分析 | **加强**，IOI 更看重"想出第一步" |
| 交互 / 提答 / 通信 | **新学**，中国体系几乎不练 |
| 字符串算法（KMP / 哈希 / SA / SAM / AC 自动机） | **降级为"了解"**，IOI Syllabus 明确排除 |
| 矩阵快速幂、FFT/NTT、LCT、二维树、最大流高效实现、SG 博弈 | **降级为"了解"**，同样被 Syllabus 排除 |
| 复杂数据结构套数据结构 | **降级**，IOI 极少考到那个深度 |

判断依据见 [syllabus-map.md](syllabus-map.md) 的五维对照表。

## 五、训练资源

| 资源 | 用途 |
| --- | --- |
| IOI 历年真题（官网 / oj.uz） | 最贴近的题型；oj.uz 保留子任务计分与公开提交 |
| APIO 真题 | 难度略低于 IOI，适合第 2–4 周 |
| CEOI / COCI | 欧洲风格，交互与构造比例高 |
| USACO Platinum | 英文题面 + 高质量数据，适合第 5–7 周 |
| CMS 文档 | 理解 Interactive / Communication / OutputOnly 三种 task type 的机制 |
| Codeforces Gym 的 IOI 赛制场 | 有子任务、有部分分，可整套 virtual |

## 六、验收：什么算"转过来了"

- [ ] 拿到一道陌生题，先看子任务表再想算法
- [ ] 30 分钟内能交出一版有分的暴力
- [ ] 能独立写交互题的本地交互器
- [ ] 提答题能稳定拿到 60 分以上
- [ ] 读英文长题面不超过 20 分钟
- [ ] 连续两天的全真模拟里，第二天不因体力崩盘

六条全过，才算完成转换；只过前两条，说明还停在"中国式训练"里。

## 七、一句话

> NOI 训练的是"把一道题做到满分"，IOI 训练的是"在 5 小时里把所有能拿的分都拿到"。前者是深度，后者是调度。
