# 高频错误与误解：症状 → 根因 → 修法

> 读这个文件当且仅当：用户说"我总是错"、"这题明明会但挂了"、"为什么别人做得比我快"。
> 用法：先让用户对照"症状"找最像的一条，再给"修法"。**不要一次列十条**，挑最像的两条。

## 一、读题与题意（失分最冤的一类）

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 样例过，提交全 WA | 把"至少"读成"至多"、"恰好"读成"不超过" | 读题时把量词圈出来，用自己的话复述一遍 |
| 答案差 1 | 边界包含关系（闭区间/开区间） | 手算 n=1、n=2 的答案，和程序对比 |
| 输出格式错 | 多空格/少换行/大小写/`Case #x:` | 复制题面的输出格式，逐字符比对 |
| 多测全挂 | 没看到 `T` 组数据 | 读题先找输入第一行是不是 T |
| 图论题方向错 | 有向/无向看漏 | 题面里"道路"通常无向，"单向"才是有向；看样例 |
| 数据范围看错 | 把 1e5 看成 1e6 | 把范围抄在代码注释第一行 |

## 二、复杂度

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| TLE 但算法"应该对" | 复杂度算错（隐藏的 O(n) 循环/多测 T） | 写出 Σ 求和式，算总操作数 |
| 多测 TLE | 每组都 O(n log n) 且 T=1e4 | 预处理共享；或改成 O(n) 每组 |
| 常数太大 | `map`/`endl`/按值传 vector | 换 `unordered_map`、`'\n'`、引用传参 |
| 递归 TLE | 重复子问题没记忆化 | 加 memo，或改递推 |
| 开了 O(n√n) 却过不了 | n=1e6 时 √n 也不小 | 换 O(n log n) 或分块优化 |

## 三、DP

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 答案偏小 | 漏了"不选/不操作"的转移 | 列出所有决策，逐个写转移 |
| 答案偏大 | 重复计数 | 固定"最后一次操作"来去重 |
| 初始化后全错 | `dp[0]` 设错（0 vs -INF） | "恰好"用 -INF，"至多"用 0 |
| 空间爆 | 没滚动数组 | 只保留前一层/前一维 |
| 转移顺序错 | 0/1 背包正序了 | 0/1 倒序、完全正序 |
| 换了问法就不会 | 状态定义绑死了"求最值" | 把状态改成"方案数/可行性"再推一遍 |

## 四、图论

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| RE | 边数没开两倍（无向图） | `2*m`，链式前向星 `tot` 从 1 开始 |
| 答案偏大 | 重边/自环没处理 | 读入时去重或特判 |
| 最短路错 | 有负权还用了 Dijkstra | 判负权 → SPFA/Bellman-Ford |
| 拓扑序不全 | 有环 | 输出节点数 < n 即有环 |
| 并查集错 | 忘了路径压缩/合并方向反 | 写 `find` 带路径压缩，`fa[fx]=fy` |
| 割点判错 | 根节点没特判 | 根子树数 ≥2 才是割点 |

## 五、数据结构

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 线段树 WA | `pushdown` 后没清标记 | 下传后清零；注意先乘后加 |
| 线段树 RE | 数组没开 4n | `4*n+5` |
| 树状数组错 | lowbit 方向错/下标从 0 | 下标从 1；`i += i&-i` |
| 平衡树 RE | `split` 边界没判空 | 先判 `!rt` 再操作 |
| 可持久化 MLE | 节点池开小 | `n*log n` 再乘常数 |
| 哈希被卡 | 单模数/自然溢出 | 双哈希 + 随机 base |

## 六、数学

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 组合数错 | 直接除没取逆元 | 预处理阶乘 + 逆阶乘 |
| 逆元不存在 | 模数非素数或 gcd≠1 | 换扩欧；或题目保证互素 |
| 负数取模错 | `(a-b)%mod` 为负 | `(a-b+mod)%mod` |
| CRT 错 | 模数不互素还用普通 CRT | 用扩展 CRT 合并 |
| 精度 WA | `double` 比较用 `==` | `fabs(a-b)<eps`，eps 取 1e-8 量级 |
| 快速幂错 | 指数没开 `long long` | 指数用 `long long` |

## 七、字符串

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 读入错 | `getline` 前有残留换行 | `cin.ignore()` 或改用 `scanf` |
| KMP 错 | `nxt[0]`/`nxt[1]` 初始化错 | 统一 0-index 写法，背一份模板 |
| 哈希冲突 | base 太小/模数被卡 | 双哈希，base 取 131/13331 并随机化 |
| Trie MLE | 节点数按字符串数开 | 节点数 = 总字符数 × 字符集 |

## 八、实现细节

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 大样例才炸 | `int` 溢出 | 乘法/累加处开 `long long` |
| 随机 WA | 越界写坏内存/未初始化 | `-fsanitize=address,undefined` 跑一遍 |
| RE 无提示 | 递归爆栈/除零 | 改迭代；判除数为 0 |
| 排序后结果乱 | 比较器不满足严格弱序 | 用 `<` 不用 `<=` |
| 输出少一行 | 最后没换行/循环少一次 | 对拍 + 逐字符比对 |

## 九、赛场策略

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 会做但没时间 | 在一题上耗太久 | 25 分钟无进展就跳 |
| 分数比预期低 | 没拿部分分 | 每题先写暴力，再优化 |
| 最后 10 分钟改出 bug | 赛中改代码无测试 | 最后 20 分钟只检查不改逻辑 |
| 文件名错 0 分 | 没养成模板习惯 | 赛前把 `freopen` 模板背下来 |
| 心态崩 | 看到别人交题 | 不看别人；按自己的节奏 |

## 十、学习方法（最隐蔽的一类）

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 刷了很多但不涨分 | 全在舒适区 | 按 3:5:2 配难度 |
| 看题解就懂，自己做不会 | 只看不写 | 24 小时后凭记忆重写 |
| 同一类题反复错 | 没做错题归因 | 每题写 3 行笔记，按 [problem-selection.md](problem-selection.md) |
| 学过的忘了 | 没有间隔重复 | 第 1/3/7/21 天各做一道同类题 |
| 只会模板题 | 没做变形/综合 | 一份题单里必须有综合题 |
| 比赛发挥不出来 | 没练过限时 | 每周至少 1 次限时赛 |

## 十一、"我以为对"的六个经典误解

1. **"复杂度 O(n log n) 一定过"** —— 要看 n 和常数。n=1e6、log 因子带大常数时，O(n log n) 也会 T。
2. **"样例过了就是对的"** —— 样例通常是最弱的数据。
3. **"贪心举不出反例就是对的"** —— 举不出反例只说明你没想到，不构成证明。
4. **"RE 是评测机的问题"** —— 99% 是自己越界/爆栈/除零。
5. **"这题我做过，直接抄"** —— 变形题抄原题 = 必挂。
6. **"看懂题解等于会了"** —— 看懂是理解，写出是实现，想出是能力，三件事。

## 十二、怎么用这份清单

1. 每次 WA/TLE 后，来这里找最像的一条，记下编号。
2. 一周后统计：哪三条出现最多？那就是你的真实短板。
3. 针对 Top 1 设计一个**具体动作**（不是"我要细心"，而是"提交前必跑 n=max 数据"）。
4. 一个月后回看，如果同一条还在，说明动作没执行，不是方法不对。
