# 调试：从"过不了"到"知道为什么过不了"

> 读这个文件当且仅当：用户说 WA / TLE / RE / MLE / 样例过但评测挂 / 不知道错在哪。
> 调试不是玄学。**先分类，再定位，最后验证**。跳过分类直接改代码，是最常见的浪费时间方式。

## 第一步：分类

| 现象 | 最可能的 5 个原因（按概率排序） | 先做什么 |
| --- | --- | --- |
| 样例就错 | 题意理解错、边界、初始化、输出格式 | 手算样例，逐行打印中间量 |
| 样例过，提交 WA | 边界数据、多测未清空、溢出、特殊情况（n=1、全相同、负数） | 造 5 组极端数据本地跑 |
| 提交 WA 在特定点 | 算法本身错（贪心无证明、DP 漏状态） | 写暴力对拍 |
| TLE | 复杂度算错、常数过大、死循环、I/O 慢 | 先算复杂度，再看循环边界 |
| MLE | 数组开太大、递归太深、vector 反复扩容 | 算内存：元素数 × 字节数 |
| RE | 数组越界、除零、栈溢出、迭代器失效、空指针 | 开 `-fsanitize=address,undefined` 重跑 |
| 答案随机波动 | 未初始化变量、越界写坏内存、哈希冲突 | 同上，先跑 sanitizer |

## 第二步：定位

### 静态检查清单（按顺序过，80% 的 bug 在这里）

1. **多测清空**：全局数组、vector、cnt、答案变量是否每组重置？
2. **溢出**：`int` 乘法（1e9 × 1e9）、`ans` 累加、`(l+r)/2`、`1<<k`。该开 `long long` 的地方开了吗？
3. **数组大小**：边数 ×2（无向图）、线段树 ×4、字符串 +1、离散化后的大小。
4. **下标**：0-index 还是 1-index？循环 `<n` 还是 `<=n`？越界读不一定崩，但会 WA。
5. **初始化**：`dis` 是否 INF？`dp[0]` 是 0 还是 -INF？并查集 `fa[i]=i`？
6. **边界**：n=1、n=2、空输入、全相同、全不同、最大值、负数、0。
7. **输出格式**：换行、空格、大小写、`Case #x:`、多输出一个空格。
8. **文件 IO**：USACO/部分 NOI 题要求 `freopen("xxx.in","r",stdin)`；文件名拼错直接 0 分。
9. **取模**：减法后 `(a-b+mod)%mod`；负数取模；模数不是素数却用了费马逆元。
10. **递归**：终止条件、深度（1e5 层会爆栈）、重复计算。
11. **图**：重边、自环、不连通、双向边只加了一条。
12. **浮点**：`==` 比较、eps 大小、`double` 精度、`printf("%.2f")` 的四舍五入。
13. **STL**：遍历时 `erase`、`priority_queue` 默认大根堆、`map` 用 `[]` 插入默认值。
14. **排序比较器**：必须严格弱序（不能 `<=`），否则 UB/RE。
15. **迭代器/引用失效**：`vector` 扩容后指针失效、`set` 元素被修改。

### 动态手段

| 手段 | 怎么做 | 什么时候用 |
| --- | --- | --- |
| 打印中间量 | 在关键位置输出状态，**先只打 1 组小数据** | 样例就错 |
| 二分注释法 | 注释掉后半段，看前半段输出对不对 | 长代码、多步骤 |
| 小数据手算 | n=1,2,3 手动推出正确答案，和程序比 | 怀疑思路 |
| 对拍 | 见下节 | 样例过但 WA |
| 重写 | 换一种写法重写核心函数 | 改了三小时越改越乱 |
| sanitizer | `g++ -fsanitize=address,undefined -g` | RE / 随机 WA / 疑似越界 |

## 第三步：对拍（最有效的验证）

对拍 = 生成器 + 暴力 + 正解 + 比较器。骨架见 `templates/stress-test.cpp`。

**关键不是跑起来，而是造得出能杀死程序的数据**。三类数据轮着来：

1. **小数据**（n ≤ 8，值域很小）：最容易暴露逻辑错误。
2. **极端数据**：全相同、严格递增/递减、全 0、全最大、一条链、菊花图、完全图。
3. **随机数据**：多组参数（n 从 1 到上限，值域从小到大），每组跑几百次。

**如果对拍一万组都不挂**：要么算法是对的（去证），要么生成器没覆盖到（换生成策略），要么暴力也错了（先验证暴力）。

## 构造 hack 数据的思路

想卡掉一个做法，问三个问题：

1. 它的复杂度在什么输入下最坏？（链 vs 菊花、全相同 vs 全不同）
2. 它的贪心/结论在什么情况下不成立？（相等元素、负数、边界）
3. 它的哈希/随机化能不能被针对性构造？（固定模数、固定种子）

## 复杂度自查

- 循环层数 × 每层次数，写出乘积，和 n 的上限比。
- 注意隐藏常数：`std::map` 每次 O(log n) 但常数大；`vector` 按值传参是 O(n)；`endl` 会 flush。
- 多测题的复杂度要乘 T：T=1e4、n=1e5 时，O(n) 每题也会超时。
- 递归/分治要写递推式：T(n)=2T(n/2)+O(n) → O(n log n)。

## 提交前的 60 秒检查

- [ ] 用最大数据跑过一遍（不是样例）
- [ ] 多测：T=1、T=max 都试过
- [ ] 边界：n=1、全相同、全 0
- [ ] 文件名/文件 IO/输出格式
- [ ] 数组大小与 long long
- [ ] 编译开 `-Wall -Wextra` 没有警告

## 心态

- 改 bug 超过 40 分钟，站起来走 10 分钟，或者换一题。疲劳时人会反复改同一行。
- 记录"这次错在哪"，一周后回看，你会发现 80% 的错误是同一类（见 [pitfalls.md](pitfalls.md)）。
- 不要用"再交一次试试"代替定位。每次提交都应该有一个假设。
