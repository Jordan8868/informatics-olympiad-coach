# 赛场：从赛前 48 小时到赛后 24 小时

> 读这个文件当且仅当：用户要打比赛、问"怎么分配时间"、"为什么总在赛场上发挥不出来"、"模拟赛怎么设计"。
> 赛场能力是**独立技能**，和你会不会算法是两件事。会做但拿不到分，问题在这里。

## 一、赛前 48 小时

| 时间 | 做什么 | 不做什么 |
| --- | --- | --- |
| T-48h | 复习模板（线段树、Dijkstra、并查集各手写一遍） | 学新算法 |
| T-24h | 做 1 场轻量模拟（2 题 2 小时），早睡 | 熬夜刷题、打高强度比赛 |
| T-12h | 检查环境：编译器版本、`freopen` 模板、文件夹结构 | 改代码习惯 |
| T-1h | 静坐、看一遍"提交前检查清单" | 和别人对答案、聊难度 |

**赛前最忌讳**：临时换编译器/换代码风格/学新东西。赛场上你只会用肌肉记忆。

## 二、赛场时间分配

### 中国 OI 赛制（4 题 4.5 小时，如 NOIP）

| 时段 | 动作 |
| --- | --- |
| 0:00–0:20 | **通读 4 题**，每题记下：数据范围、大致算法、暴力分怎么拿 |
| 0:20–1:20 | 做最有把握的一题，**先写暴力再优化** |
| 1:20–2:30 | 第二题；若卡住超过 25 分钟，跳到第三题 |
| 2:30–3:40 | 第三题；同时回头补前两题的部分分 |
| 3:40–4:10 | 第四题暴力分（能拿多少拿多少） |
| 4:10–4:30 | **检查**：文件名、`freopen`、多测清空、数组大小、输出格式 |

**核心原则**：4 题里通常 2 题可做、1 题半可做、1 题很难。**先把可做的做完做对，再啃半可做的。**

### IOI 赛制（3 题 5 小时）

| 时段 | 动作 |
| --- | --- |
| 0:00–0:20 | 读 3 题 + **读子任务表**（这是 IOI 特有的信息） |
| 0:20–1:00 | 每题交一版暴力，先把"保底分"锁死 |
| 1:00–3:30 | 按"性价比"排序攻子任务：能拿大档的先做 |
| 3:30–4:40 | 优化/调试；每次提交都只赚不亏 |
| 4:40–5:00 | 确认每题都有非零分，检查边界 |

**IOI 的红利**：子任务取历次提交最大值。所以**先交暴力是纯赚**，不交才是亏。

### Codeforces（Div.2，2 小时 5–6 题）

| 时段 | 动作 |
| --- | --- |
| 0:00–0:10 | 快速扫 A–C（A 通常 2 分钟） |
| 0:10–0:50 | A、B 拿下（罚时敏感，别恋战） |
| 0:50–1:30 | C，然后 D |
| 1:30–2:00 | 有思路的题继续，没思路的放弃 |

**CF 的坑**：pretest 过 ≠ AC。每题交之前自己造一组极限数据（n 最大、全相同、边界）。

### 初赛（笔试，120 分钟）

| 时段 | 动作 |
| --- | --- |
| 0–40 分钟 | 单选（15 题，30 分），不会的先标记 |
| 40–80 分钟 | 阅读程序（3 大题，40 分），逐行模拟 |
| 80–110 分钟 | 完善程序（2 大题，30 分） |
| 110–120 分钟 | 检查填涂、补标记题 |

## 三、开题顺序与止损

**开题顺序**：先通读，再按"把握 × 分值"排序，不按题号。

**止损规则**（很重要）：

- 一道题想 25 分钟没有任何进展 → 立刻跳。
- 一道题调 40 分钟还在 WA → 先放着，去拿别的分。
- 一道题写完发现思路错了 → 保留暴力分，不要全部删掉重写。

**为什么**：4.5 小时里，卡在一题上损失的不是那题的 100 分，而是另外三题的机会成本。

## 四、部分分策略（中国 OI / IOI 通用）

拿到一道题，先问三个问题：

1. **暴力能拿多少分？**（n≤10 的枚举、n≤100 的 O(n^3)、特殊性质）
2. **特殊性质能不能拿？**（链、菊花、全相同、a_i=1）
3. **正解需要哪个前置结论？**

**能拿 60 分暴力 + 20 分特殊性质 = 80 分，比死磕 100 分正解最后 0 分强得多。**

写暴力的三个要点：单独开文件/函数、不要和正解混在一起、注释清楚"这版是暴力"。赛中改错版本是常见事故。

## 五、提交前的 60 秒检查

- [ ] 文件名、`freopen` 路径、大小写
- [ ] 多测：清空了吗？T=1 和 T=max 都试过吗？
- [ ] 数组大小：边 ×2、线段树 ×4、字符串 +1
- [ ] `long long`：乘法、累加、`(l+r)/2`
- [ ] 输出格式：换行、空格、`Case #`
- [ ] 极限数据跑过一遍（n=max、全相同、全 0）
- [ ] 暴力版本还在（万一正解挂了）

## 六、心态

- **不要看别人的进度**。赛场上的"别人"通常只是先交了暴力。
- **卡住时站起来 2 分钟**，喝口水。疲劳时人会反复改同一行。
- **把大目标拆成小目标**："这小时拿到第二题"比"我要 AK"有用。
- **接受部分分**。NOIP 250 分是省一水平，不是 400。
- **最后 20 分钟不要开新题**，用来检查。

## 七、赛后 24 小时复盘

赛后立刻做，隔天就忘。用 `templates/post-mortem.md`。

| 项 | 内容 |
| --- | --- |
| 分数 | 实际 / 预期 / 差距 |
| 每题失分类型 | 读题 / 思路 / 实现 / 复杂度 / 策略 / 心态 |
| 当时怎么想的 | 一句话还原现场（不是"我太菜了"） |
| 正确第一步 | 如果重来，第一件事做什么 |
| 下次触发 | 具体动作，例如"看到 n≤5000 先想 O(n^2) 而不是 O(n)" |

**把"粗心"翻译成动作**：粗心 = 没有检查机制。动作 = "提交前必跑 n=max 数据"。

## 八、模拟赛怎么设计

| 目标赛事 | 题数 | 时长 | 难度曲线 |
| --- | --- | --- | --- |
| CSP-J | 4 | 3.5h | 易 / 易中 / 中 / 难 |
| CSP-S / NOIP | 4 | 4–4.5h | 中易 / 中 / 中难 / 难 |
| 省选 | 3 | 5h | 中 / 难 / 很难 |
| IOI | 3 | 5h | 中 / 中难 / 难（带子任务） |
| CF Div.2 | 5–6 | 2h | A→F 递增 |

**出题来源**：往年真题最稳；自己组卷时从 `data/topics.json` 的 `probs` 取，或按 [problem-selection.md](problem-selection.md) 的检索式找。

**赛后 30 分钟讲解大纲**：每题讲三件事——考什么、关键一步、最常见的错法。不逐行念代码。

## 九、赛场十大事故（每年都有人犯）

1. 文件名写错 / 没有 `freopen` → 0 分
2. 多测没清空 → 后面全 WA
3. 数组开小 → RE 或随机 WA
4. `int` 溢出 → 大样例才炸
5. 交错了题（A 的代码交到 B）→ 两题都 0
6. 只交暴力忘了改正解 → 少几十分
7. 最后 5 分钟改代码 → 改出新 bug
8. 读错题（"至少"看成"至多"）→ 全盘皆错
9. 没看数据范围，写了 O(n^2) 正解 → TLE
10. 不会做就空着 → 连暴力分都没有
