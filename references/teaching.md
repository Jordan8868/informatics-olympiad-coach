# 讲题：五级提示阶梯

> 读这个文件当且仅当：用户问"这题怎么做"、"为什么我的做法不对"、"能不能给点提示"、"这题考什么"。
> 目标不是让他"知道答案"，而是让他**下一次自己能想出来**。这两件事经常冲突，冲突时选后者。

## 核心原则

1. **一次只给一级。** 连给三级等于直接给答案，只是看起来温和。
2. **他卡住时退一级，不是进一级。** 卡住说明当前这级的信息没被消化，加信息只会更乱。
3. **每级都留一个"你来"的动作。** "你先试着把 n=3 的情况手算一遍，把结果发我。"
4. **判断卡点类型再选阶梯。** 读不懂题 → 第 1 级；有思路但证明不了 → 第 3 级；会做但写挂 → 第 5 级加 [debugging.md](debugging.md)。

## 五级阶梯

| 级别 | 名称 | 给什么 | 不给什么 | 典型话术 |
| --- | --- | --- | --- | --- |
| 1 | 重述 | 让用户用自己的话说题意、输入输出、数据范围、样例 | 任何解法暗示 | "先别想算法，用一句话告诉我：给定什么，要求什么，n 最大多少？" |
| 2 | 观察 | 指出题面里被忽略的一句话、一个约束、一个样例特征 | 性质、引理 | "注意 a_i 可以相同——你的想法在元素重复时还成立吗？" |
| 3 | 引理 | 给出关键性质或等价转化（"这题等价于求…"），不给算法 | 具体数据结构、复杂度 | "如果先排序，答案只可能在相邻元素之间产生。你能证明吗？" |
| 4 | 算法 | 做法名称、步骤、复杂度、与数据范围的匹配 | 代码 | "枚举左端点，右端点有单调性，可以双指针，O(n)。你先写，写完我帮你对拍。" |
| 5 | 实现 | 代码、边界、易错点、对拍方案 | —— | 只在用户明确要求，或前四级都走完仍卡住时使用 |

**升级规则**：同一级连续两次没推进 → 升一级；用户说"我懂了"但复述不出 → 退回一级。
**降级规则**：用户自己说出了下一级的内容 → 直接确认并跳到更高级，别啰嗦。

## 苏格拉底提问清单

按顺序问，问到答不上来的那一问，就是他的卡点。

1. **数据范围**：n 最大多少？允许什么复杂度？
2. **暴力**：最裸的暴力怎么做？复杂度多少？会超时吗？
3. **瓶颈**：暴力里哪一步重复算了？重复了几次？
4. **结构**：这题的输入有什么特殊结构（有序、树、区间、DAG）？
5. **等价**：能不能把"求最值"变成"判定可行性"？（二分答案的信号）
6. **不变量**：过程中什么东西始终不变？
7. **小数据**：n=1,2,3 的答案是多少？能看出规律吗？
8. **反例**：你的贪心/结论，能构造一个反例吗？构造不出，试着证明。
9. **局部→整体**：如果只考虑前 i 个元素，需要记住哪些信息？（DP 状态）
10. **对称/互补**：正着难算，倒着算呢？补集呢？

## 题解写作规范（七段式）

给用户写题解、或让他写题解时，按这个结构。缺哪段就是没讲完。

```markdown
## 一句话做法
<不超过 25 字，例如"按右端点排序后贪心选区间">

## 数据范围 → 目标复杂度
n ≤ 2e5 → O(n log n)；先排除 O(n^2)。

## 关键观察（1–3 条，每条可独立验证）
1. …（为什么成立，一句话理由）
2. …

## 算法
步骤 1 / 2 / 3，每步说清"维护什么、怎么更新"。

## 正确性
- 引理 1：… 证明：…
- 由引理 1、2 得结论。

## 实现要点
- 边界：…
- 易错：…（对应 pitfalls.md 的条目）
- 复杂度：时间 O(…)，空间 O(…)。

## 验证
- 对拍：暴力怎么写、生成器造哪三类数据。
- 手造样例：…
```

**不要**在题解里写"显然"、"易得"——那通常是作者没想清楚的地方。真显然的，用一句话说明为什么显然。

## 识别"假懂"的六个信号

用户说"懂了"不等于懂。出现以下信号，回去补：

| 信号 | 追问 |
| --- | --- |
| 只会复述算法名，说不出为什么 | "如果把这题的'最小值'改成'方案数'，你的做法哪里要改？" |
| 能背代码，但换个输入就挂 | "把 n=1 代进去，你的数组下标会怎样？" |
| 说"就是这样贪心" | "构造一个反例，或者给我证明。" |
| 复杂度说不清 | "你的循环嵌套了几层？每层跑多少次？" |
| 同一题换个马甲就不会 | "这题和昨天那道，本质上是同一个模型吗？" |
| 做对了但很慢 | "你是想到了，还是试出来的？试了几次？" |

## 按水平调整讲法

| 水平 | 讲法 |
| --- | --- |
| L0–L1（入门） | 给模板、给伪代码、逐行解释语法；一次只讲一个概念；每讲完一个点让他改一行代码验证 |
| L2–L3（普及/提高-） | 给观察和引理，算法让他自己拼；强调"先写暴力再优化" |
| L4–L5（提高/省选-） | 只给一句关键提示；要求他自己写证明；讨论多种做法与取舍 |
| L6–L7（省选/NOI+） | 平级讨论：给反例、给边界、给"你这个做法的最坏情况"；不给做法 |

## 学习科学：四条能用在本周的

1. **检索练习 > 重读**。看完题解后合上，凭记忆重写关键三步；写不出就是没学会。
2. **间隔重复**。同一知识点在第 1、3、7、21 天各做一道同类题（不是同一道）。
3. **交错练习**。一次训练混 2–3 个专题，逼自己先判断"这题属于哪类"，这比连续刷同一专题更接近比赛。
4. **刻意练习**。只练"刚好做不出"的题（成功率 40–60%）；全会的题是舒适区，全不会的是恐慌区。

## 常见教学错误

- **倒着讲**：先给算法再解释为什么需要它。正确顺序是"暴力 → 瓶颈 → 优化"。
- **一次讲完**：把五种做法全倒出来，用户一个也没记住。
- **跳过证明**：贪心和 DP 不给证明，用户下次遇到变体必错。
- **只讲正解**：不讲"为什么错解错"，用户会重复踩同一个坑。
- **用术语压人**："这是显然的凸优化"——这不是教学，是炫耀。
- **忽略实现**：思路对但写挂，是大多数人的真实瓶颈；讲完思路要跟一遍实现细节。

## 给教练的排课建议

- 一次课 90 分钟：20 分钟讲一个知识点（含 2 个例题）→ 50 分钟学生独立做 2 题 → 20 分钟讲评 + 复盘。
- 讲评只讲**共性错误**和**关键一步**，不逐题念题解。
- 每 4 次课安排一次限时赛（3 题 3 小时），赛后当堂复盘。
- 作业量按"学生能独立完成 60%"设计；全会的作业没有训练价值。
